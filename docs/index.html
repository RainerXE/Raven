The Raven manual

Raven is a GUI library in C11 for editors and tools: native windows on Windows, Linux and macOS, drawn with Vulkan, with a layout in the manner of Slate, interfaces written in XML or in code, a text editor for code, docking, glass materials, translations, accessibility, and bindings for seven other languages. This guide explains every part of it with examples. The two other pages are references: every XML tag and attribute, and every function of the C API.

Raven 0.1. The public API may still change before 1.0.

1. A first program

The whole API is one include. A window, a box, a label and a button:

#include <Raven.h>

static void on_quit(Rid button, void* user_data) {
    (void)button;
    (void)user_data;
    Rquit(0);
}

int main(void) {
    if (!Rinit(R_BACKEND_VULKAN)) return 1;

    Rid window = Rwindow_create("Hello", 420, 220, R_WINDOW_DEFAULT);
    Rid box = Rwidget_create(R_WIDGET_VBOX);
    Rpanel_set_spacing(box, 12);
    Rslot_set_halign(box, R_HALIGN_CENTER);
    Rslot_set_valign(box, R_VALIGN_CENTER);
    Rwindow_set_content(window, box);

    Rwidget_add_child(box, Rlabel_create("Hello from Raven"));
    Rid quit = Rwidget_add_child(box, Rbutton_create("Quit"));
    Rbutton_set_clicked_callback(quit, on_quit, NULL);

    while (Rwait_frame(-1.0)) {}
    Rshutdown();
    return Rget_exit_code();
}

The same window, written in XML and loaded by the program:

<Window Title="Hello" Width="420" Height="220">
    <VBox Spacing="12" Slot.HAlign="Center" Slot.VAlign="Center">
        <Label>Hello from Raven</Label>
        <Button Text="Quit" OnClicked="app.quit"/>
    </VBox>
</Window>
#include <Raven.h>

static void on_quit(Rid sender, const char* action, void* user_data) {
    (void)sender;
    (void)action;
    (void)user_data;
    Rquit(0);
}

int main(void) {
    if (!Rinit(R_BACKEND_VULKAN)) return 1;
    Raction_bind("app.quit", on_quit, NULL);
    if (Rwindow_create_from_xml_file("hello.xml") == R_INVALID_ID) return 1;
    while (Rwait_frame(-1.0)) {}
    Rshutdown();
    return 0;
}

Built with CMake, against an installed Raven:

project(hello C)
find_package(raven REQUIRED)            # -DCMAKE_PREFIX_PATH=<the Raven package>
add_executable(hello main.c)
target_link_libraries(hello PRIVATE raven::raven)

Or with the interface and its code in one file, main.xmlc (see XMLC), which the IDE creates for you.

2. Building Raven

Raven needs CMake 3.16 or newer and a C11 compiler. On Linux it also needs the X11 development package. The Vulkan headers are taken from the Vulkan SDK when it is installed and downloaded during the configuration otherwise; no Vulkan library is linked (it is loaded when the program runs). Each build gives the library, ravenc (the XMLC compiler), the IDE, the examples and the tests.

Windows

With Visual Studio 2022 (workload Desktop development with C++), in the Developer PowerShell:

git clone https://github.com/oscar-soirey/Raven.git
cd Raven
cmake -S . -B build
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
cmake --install build --config Release --prefix install

Booleans are int (R_TRUE, R_FALSE), colors are four floats from 0 to 1, strings are UTF-8 and always copied by the library. A string returned by the library stays valid until the next call that returns one of the same kind: copy it to keep it.

Handles and errors

Every object is a Rid: windows, widgets, fonts, textures, timers, tree items, documents. A handle carries a generation, so using a deleted object is reported instead of crashing, and R_INVALID_ID is returned on failure. Deleting a widget deletes its children; deleting a window deletes its content.

static void on_error(RError code, RSeverity severity, const char* detail) {
    fprintf(stderr, "[%s] %s: %s\n", Rseverity_to_string(severity), Rerror_to_string(code), detail);
}

Rerror_set_callback(on_error);        /* before Rinit, to see its errors too */

const char* detail;
RSeverity severity;
if (Rerror_get_last(&detail, &severity) != R_NO_ERROR) puts(detail);

The loop

Raven has no loop of its own. The application asks for one frame at a time:

while (Rdraw_frame()) {               /* a game or an engine: never waits    */
    update_and_render_my_scene();
}

while (Rwait_frame(-1.0)) {}          /* a tool: sleeps until something happens */

Rdraw_frame processes the events, runs the timers and the posted tasks, lays out, paints and submits the windows that changed; a window in which nothing changed is not drawn again. Rwait_frame first sleeps until there is something to do (an event, a timer, an animation still moving, a task); its argument is the longest sleep in seconds, negative for no limit. Both return R_FALSE once Rquit was called or the last window closed; Rget_exit_code gives the code. Rset_frame_callback runs a function once per frame, also while the system holds the thread in a loop of its own (on Windows, while a window is moved or resized).

RInitDesc desc = { 0 };               /* zero: the default of every field */
desc.backend = R_BACKEND_VULKAN;
desc.app_name = "My tool";
desc.worker_threads = 0;              /* one per spare core; negative: none */
desc.ui_scale = 1.25f;                /* on top of the scale of the monitor */
desc.disable_vsync = R_FALSE;
desc.enable_validation = R_FALSE;     /* the Vulkan validation layer, when installed */
if (!Rinit_ex(&desc)) return 1;

One thread for the interface

The thread that called Rinit is the UI thread: every function is called from it, except those documented as thread-safe (Rtask_post, Rtask_run_async, Rwake_up, Rquit, Rwindow_request_redraw, Rget_time, Rmemory_alloc, Rmemory_realloc, Rmemory_free, Rmemory_get_stats). Another thread changes the interface by posting a task (Threads). A call from the wrong thread is reported as R_ERROR_WRONG_THREAD.

5. Widgets

An interface is a tree of widgets. A widget is created by type, put in a parent, found again by name, and deleted with its children:

Rid panel  = Rwidget_create(R_WIDGET_VBOX);
Rid label  = Rwidget_add_child(panel, Rlabel_create("Name"));     /* returns the child */
Rid input  = Rwidget_add_child(panel, Rwidget_create(R_WIDGET_TEXT_INPUT));
Rwidget_set_name(input, "name");

Rid found  = Rwidget_find(window, "name");          /* in a window, or under any widget */
Rid parent = Rwidget_get_parent(found);
int count  = Rwidget_get_child_count(panel);
Rwidget_insert_child(panel, Rbutton_create("First"), 0);
Rwidget_remove_child(panel, label);                 /* removed and deleted */
Rwidget_clear_children(panel);
Rwidget_destroy(panel);

The types: panels (R_WIDGET_VBOX, R_WIDGET_HBOX, R_WIDGET_GRID, R_WIDGET_UNIFORM_GRID, R_WIDGET_OVERLAY, R_WIDGET_BORDER, R_WIDGET_SIZE_BOX, R_WIDGET_SPACER, R_WIDGET_SCROLL_BOX, R_WIDGET_SPLITTER, R_WIDGET_WRAP_BOX, R_WIDGET_CANVAS, R_WIDGET_SWITCHER, R_WIDGET_TAB_VIEW, R_WIDGET_EXPANDER, R_WIDGET_BACKGROUND_BLUR), controls (R_WIDGET_LABEL, R_WIDGET_BUTTON, R_WIDGET_CHECKBOX, R_WIDGET_SLIDER, R_WIDGET_PROGRESSBAR, R_WIDGET_IMAGE, R_WIDGET_TEXT_INPUT, R_WIDGET_SPIN_BOX, R_WIDGET_COMBO_BOX, R_WIDGET_SEPARATOR, R_WIDGET_LIST_VIEW, R_WIDGET_TREE_VIEW, R_WIDGET_TILE_VIEW, R_WIDGET_MENU_BAR, R_WIDGET_MENU, R_WIDGET_MENU_ITEM, R_WIDGET_TEXT_EDITOR), the shell (R_WIDGET_HEADER_BAR, R_WIDGET_DOCK_AREA, R_WIDGET_ISLAND, R_WIDGET_FILE_BROWSER), tools (R_WIDGET_COLOR_PICKER, R_WIDGET_TIMELINE, R_WIDGET_NODE_GRAPH, R_WIDGET_BLOCK_EDITOR) and your own (R_WIDGET_VIEWPORT, R_WIDGET_CUSTOM).

6. Layout

Layout is the two passes of Slate: each widget computes the size it wants, from the leaves up; then each panel gives a rectangle to its children, from the root down. How a child is placed is stored on the child, in its slot, and read by its parent:

Rid row  = Rwidget_add_child(parent, Rwidget_create(R_WIDGET_HBOX));
Rpanel_set_spacing(row, 8);
Rid name = Rwidget_add_child(row, Rwidget_create(R_WIDGET_TEXT_INPUT));
Rslot_set_fill(name, 1.0f);                   /* takes the free width */
Rid ok   = Rwidget_add_child(row, Rbutton_create("OK"));
Rslot_set_valign(ok, R_VALIGN_CENTER);        /* its own height, centered */
Rslot_set_padding(ok, 8, 0, 0, 0);            /* left, top, right, bottom */
SlotRead by
Rslot_set_paddingevery panel
Rslot_set_halign (R_HALIGN_FILL, _LEFT, _CENTER, _RIGHT)VBox, Grid, Overlay, Border, SizeBox, ScrollBox, Switcher, a window
Rslot_set_valign (R_VALIGN_FILL, _TOP, _CENTER, _BOTTOM)HBox, Grid, Overlay, Border, SizeBox, ScrollBox, Switcher, a window
Rslot_set_fill, Rslot_set_auto, Rslot_set_max_sizeVBox, HBox; Splitter (share of each pane)
Rslot_set_grid, Rslot_set_grid_spanGrid, UniformGrid
Rslot_set_anchors, Rslot_set_position, Rslot_set_size, Rslot_set_alignmentCanvas
Rslot_set_titleTabView, DockArea

Sizes are logical units, multiplied by the scale of the monitor. Only the part of the tree that changed is measured and arranged again.

R_WIDGET_OVERLAY stacks its children (the last on top), R_WIDGET_WRAP_BOX flows them and wraps to the next line, R_WIDGET_SIZE_BOX forces a size or an aspect ratio (Rsize_box_set_aspect_ratio), R_WIDGET_SPACER is empty space.

Right to left

A language written from right to left mirrors the layouts: boxes, grids, menus, scroll bars and alignments start on the right. By default (R_DIRECTION_AUTO) the windows follow the language in use; Rset_layout_direction(R_DIRECTION_RTL) or R_DIRECTION_LTR forces one direction for every window, and Rwidget_set_direction gives one to a part of a window (R_DIRECTION_INHERIT goes back to its parent; Direction="RightToLeft" in XML).

8. Events and actions

Callbacks

Each control has typed callbacks for its events (clicked, changed, committed, activated...), set with `R..._set_..._callback(widget, function, user_data)`. The last argument is given back to the function as it is.

Actions

An action is a name for what the main event of a widget does: a click of a button or of a menu item, a change of a checkbox, Enter in a text input, the activation of a row. Interfaces written in XML use them (OnClicked="file.save"); from C, Rwidget_set_action gives one to a widget.

static void on_action(Rid sender, const char* action, void* user_data) {
    if (strcmp(action, "file.save") == 0) save_document();
}

Raction_bind("file.save", on_action, NULL);
Raction_bind("file.open", on_action, NULL);
Raction_set_default_handler(on_action, NULL);   /* the actions bound to nothing */
Raction_fire("file.save", R_INVALID_ID);        /* from code */
Raction_unbind("file.open");

Keyboard shortcuts

Rwindow_register_shortcut(window, R_KEY_S, R_MOD_CTRL, "file.save");
Rwindow_register_shortcut(window, R_KEY_Z, R_MOD_CTRL | R_MOD_SHIFT, "edit.redo");
Rwindow_unregister_shortcut(window, R_KEY_S, R_MOD_CTRL);

The shortcut of a menu item works by itself; in XML, <Shortcut Keys="Ctrl+S" Action="file.save"/>. The modifiers are R_MOD_CTRL, R_MOD_SHIFT, R_MOD_ALT and R_MOD_SUPER. Tab and Shift+Tab move the focus between the controls (Rwindow_set_tab_navigation turns it off).

Raw input

A widget can see the mouse and the keyboard before its own class does; returning R_TRUE consumes the event. Events bubble from the widget under the pointer (or with the focus) up to the window.

static int on_event(Rid widget, const REvent* e, void* user_data) {
    switch (e->type) {
    case R_EVENT_MOUSE_DOWN:
        if (e->button == R_MOUSE_RIGHT) { open_menu(e->x, e->y); return R_TRUE; }
        if (e->clicks == 2) { rename_item(); return R_TRUE; }
        break;
    case R_EVENT_MOUSE_WHEEL:
        zoom_by(e->wheel_y);
        return R_TRUE;
    case R_EVENT_KEY_DOWN:
        if (e->key == R_KEY_DELETE && !(e->modifiers & R_MOD_CTRL)) { delete_selection(); return R_TRUE; }
        break;
    case R_EVENT_TEXT:          /* e->codepoint: a typed character */
    default:
        break;
    }
    return R_FALSE;             /* not mine: the widget and its parents get it */
}

Rwidget_set_event_callback(widget, on_event, NULL);
Rwindow_set_event_hook(window, on_window_event, NULL);   /* the whole window, before any widget */

REvent gives the position in the window (x, y) and in the widget (local_x, local_y), the movement (delta_x, delta_y), the wheel, the button and the number of clicks, the key, the modifiers, whether the key repeats and the typed character.

Drag and drop

Files and text dragged from other applications are dropped on a window or on a widget:

static int on_drop(Rid target, const RDropEvent* e, void* user_data) {
    if (e->phase == R_DROP_DROPPED) {
        int i;
        for (i = 0; i < e->path_count; i++) open_file(e->paths[i]);
        if (e->text) insert_text(e->text);
    }
    return R_TRUE;              /* "I take it": the target is highlighted while it is over it */
}

Rwindow_set_drop_callback(window, on_drop, NULL);
Rwidget_set_drop_callback(panel, on_drop, NULL);

Inside the application, Rdrag_begin drags a text with a type, while a mouse button is held; the drop callbacks receive drag_type, drag_source and the data in text, and can refuse it by returning R_FALSE. Tree views and tile views start their drags themselves (Rtree_view_set_drag_type, Rtile_view_set_drag_type).

/* in the event callback of the source, once the pointer has moved a few units */
Rdrag_begin(source, "asset", "textures/wood.png", "wood.png");

static int on_asset_drop(Rid target, const RDropEvent* e, void* user_data) {
    if (!e->drag_type || strcmp(e->drag_type, "asset") != 0) return R_FALSE;
    if (e->phase == R_DROP_DROPPED) apply_asset(target, e->text);
    return R_TRUE;
}

Dragging out of a Raven window to another application is not implemented.

9. Interfaces in XML

Every widget, attribute and slot has an XML spelling. A document is loaded into widgets, which are then handles like the others. The XML reference lists every tag and attribute; this section is about using it from a program.

Live reload

A window created from a file follows the file: save main.xml in any editor while the program runs and the window changes, keeping the widgets that are still there with their handles, their callbacks and what was typed. Rxml_set_reload_callback tells after each reload, Rxml_set_live_reload turns it off (or RAVEN_LIVE_RELOAD=0). Theme files, the files of declared tags and the tables of translations are watched the same way.

Tags of your own

A document declares tags with <Widget Name="Card" Title="">, with parameters, expressions, <Children/>, <Repeat>, <ForEach>, <If> and <Include> (Declaring tags). From C, Rxml_register_widgets_from_file("ui/widgets.xml") reads declarations ahead of the documents that use them, and Rxml_register_tag gives a tag to a widget built by code (Tags made by code).

10. One file, any language: XMLC

An interface and the code that goes with it can be one file: the XML, and its code in <script> elements. ravenc turns the whole file into a source of your language: the scripts are copied as they are, and the XML becomes tables built by Rwindow_create_from_compiled (no XML is read when the program runs). OnClicked="{on_save}" calls the function on_save of the scripts, ui.status is the widget named status, and the compiler of the language checks all of it.

<!-- main.xmlc: a whole C program -->
<script>

static void on_hello(Rid sender, const char* action, void* user_data) {

16. Custom widgets, drawing and animation

A R_WIDGET_CUSTOM is measured and painted by two callbacks, and receives its input through Rwidget_set_event_callback. Coordinates are logical units from its top left corner.

#include <Raven.h>

typedef struct gauge_t {
    float level;          /* 0..1 */
    RSpring shown;        /* the level drawn, gliding to `level` */
} gauge_t;

static void gauge_measure(Rid widget, float* width, float* height, void* user_data) {
    (void)widget; (void)user_data;
    *width = 160;
    *height = 18;
}

static void gauge_paint(Rid widget, RPainter* p, float width, float height, void* user_data) {
    gauge_t* g = (gauge_t*)user_data;
    float level = Rdraw_spring(p, &g->shown, g->level, R_MOTION_BOUNCY);
    float r, gr, b, a;
    (void)widget;
    Rtheme_get_color(R_COLOR_ACCENT, &r, &gr, &b, &a);
    Rdraw_rect(p, 0, 0, width, height, height * 0.5f, 1, 1, 1, 0.08f);
    Rdraw_rect(p, 0, 0, width * level, height, height * 0.5f, r, gr, b, a);
    Rdraw_text(p, R_INVALID_ID, 11, 8, 2, level > 0.9f ? "full" : "", 1, 1, 1, 1);
}

static int gauge_event(Rid widget, const REvent* e, void* user_data) {
    gauge_t* g = (gauge_t*)user_data;
    float x, y, w, h;
    if (e->type != R_EVENT_MOUSE_DOWN) return R_FALSE;
    Rwidget_get_rect(widget, &x, &y, &w, &h);
    g->level = e->local_x / w;
    Rwidget_invalidate(widget);           /* paint again */
    return R_TRUE;
}

static gauge_t g_gauge = { 0.4f, { 0.0f, 0.0f, 0 } };

int main(void) {
    Rid window, gauge;
    if (!Rinit(R_BACKEND_VULKAN)) return 1;
    window = Rwindow_create("Gauge", 320, 120, R_WINDOW_DEFAULT);
    gauge = Rwidget_create(R_WIDGET_CUSTOM);
    Rcustom_set_measure_callback(gauge, gauge_measure, &g_gauge);
    Rcustom_set_paint_callback(gauge, gauge_paint, &g_gauge);
    Rwidget_set_event_callback(gauge, gauge_event, &g_gauge);
    Rslot_set_halign(gauge, R_HALIGN_CENTER);
    Rslot_set_valign(gauge, R_VALIGN_CENTER);
    Rwindow_set_content(window, gauge);
    while (Rwait_frame(-1.0)) {}
    Rshutdown();
    return 0;
}

The painter draws rounded rectangles and their outlines, circles, lines, curves, triangles, images, text and glass (Rdraw_glass), clipped with Rdraw_push_clip_rect. Rxml_register_tag gives such a widget a tag of its own (XML).

Springs

Everything moves with springs, as on a phone: buttons squash and bounce back, switches slide, popups pop out of what opened them, lists stretch at their ends. In a custom widget, Rdraw_spring pulls a value to its target and keeps the window drawing while it moves; Rwait_frame sleeps again when everything rests. The motions are R_MOTION_SNAPPY, R_MOTION_SMOOTH, R_MOTION_BOUNCY and R_MOTION_WOBBLY; Rspring_kick gives a spring a push, Rspring_set puts it somewhere without moving.

23. Threads

The thread of Rinit owns the interface. A render thread owns the GPU, and a job system of worker threads paints large trees in parallel and runs your work.

typedef struct job_t { char path[260]; char* result; } job_t;

static void job_done(void* user_data) {           /* on the UI thread */
    job_t* job = (job_t*)user_data;
    Rtext_editor_set_text(g_editor, job->result);
    Rmemory_free(job->result);
    Rmemory_free(job);
}

static void job_run(void* user_data) {            /* on a worker thread: no widget here */
    job_t* job = (job_t*)user_data;
    job->result = load_and_format(job->path);
    Rtask_post(job_done, job);                    /* back to the UI thread, and wakes Rwait_frame */
}

job_t* job = (job_t*)Rmemory_alloc(sizeof(job_t));
snprintf(job->path, sizeof(job->path), "%s", path);
Rtask_run_async(job_run, job);

/* split a loop over the workers and this thread; returns when all is done */
static void blur_rows(Ruint begin, Ruint end, void* image) { /* rows begin..end-1 */ }

Viewport draw callbacks run on the render thread. Rwake_up wakes Rwait_frame from any thread; Ris_ui_thread tells where you are.

24. Memory

Raven does not call malloc: it takes memory from the system by regions of 4 MB and hands it out with its own heap (TLSF: constant time, neighbours merged when freed). The bundled font and image decoders use it too.

static void* my_alloc(size_t size, void* user) { return engine_alloc(size, 16); }
static void* my_realloc(void* p, size_t size, void* user) { return engine_realloc(p, size, 16); }
static void my_free(void* p, void* user) { engine_free(p); }

RAllocator mine = { my_alloc, my_realloc, my_free, NULL };
Rset_allocator(&mine);                 /* before Rinit: every block goes through your functions */

RMemoryStats stats;
Rmemory_get_stats(&stats);             /* bytes in use, peak, blocks, taken from the system */
printf("%zu bytes in %zu blocks\n", stats.used_bytes, stats.allocation_count);
Rmemory_check();                       /* walks the heap: R_FALSE when it is corrupted */
Rmemory_trim();                        /* gives back the regions that hold nothing */

Rset_allocator(Rallocator_get_system()), or RAVEN_ALLOCATOR=system, uses malloc instead (what Valgrind and heap profilers follow; the default in a build with AddressSanitizer). After Rshutdown, allocation_count is 0: anything else is a leak of the library.

int main() {
    raven::init(R_BACKEND_VULKAN);
    auto window = raven::Window::create("Hello", 400, 200, R_WINDOW_DEFAULT);
    auto button = raven::Button::create("Quit");
    button.set_clicked_callback([](Rid) { raven::quit(0); });     /* any callable, captures included */
    window.set_content(button);
    while (raven::wait_frame(-1.0)) {}
    raven::shutdown();
}

A class per kind of handle, whose member functions are the C functions of that object (Rbutton_set_text(button, "OK") is button.set_text("OK")); a class is the size of a handle and does not own what it names.

Rust

use raven::*;

fn main() {

The crate raven-gui (imported as raven): the C API as it is, plus text, cstr, action_bind, window_from_xml and widget_find. Its build.rs links the library from RAVEN_LIB_DIR (RAVEN_STATIC=1 for the static one).

Rwindow_set_title is WindowSetTitle; texts are strings; what a C function writes through a pointer is a result. Build with CGO_CFLAGS="-I<raven>/include" and CGO_LDFLAGS="-L<folder of the library>".

C#

using Raven;

R.Rinit(RBackend.R_BACKEND_VULKAN);
uint window = R.Rwindow_create_from_xml("<Window Title='Hi'><Button Text='Quit' OnClicked='quit'/></Window>");

P/Invoke. R.Keep keeps a delegate away from the garbage collector while the library may call it; the shared library goes beside the program.

fn quit(sender: r.Rid, action: ?[*:0]const u8, user_data: ?*anyopaque) callconv(.C) void {

26. The IDE

raven_designer [project folder | file] is the IDE of Raven, written with Raven. It opens on a start page: new project, open a folder, the recent projects.

Projects

Project > New project (Ctrl+Shift+N) asks a name, a language (C, C++, Rust, Python, Go, C#, Zig, Lua), a location, and a kind:

  • Raven interface + code: the interface and its code in one main.xml... (XMLC), the files of the tools of the language (CMakeLists.txt, Cargo.toml and build.rs, go.mod, .csproj, build.zig) and strings.csv. It builds as it is.
  • Native: the language alone, a classic Hello world and what its tools need (main.c and a CMakeLists.txt, src/main.rs and a Cargo.toml, main.py, main.go and a go.mod, Program.cs and a .csproj, src/main.zig and a build.zig, main.lua). Nothing of Raven.

The content drawer (Ctrl+Space, from anywhere) shows the files of the project as tiles: a double click opens a file where it belongs, a right click offers Open and, for an interface, Preview; the search looks through the whole project.

Code, and the island as a preview

Every file opens in a code editor tab: C, C++, Rust, Python, Go, C#, Zig, Lua, CMake, XML and the XMLC files, with completion of the Raven API (read from its headers), of the widgets of the interface (ui.<Name>), of the tags, attributes and @keys. Ctrl + wheel zooms the text of every editor at once, and the zoom is kept for the next time.

When the file in front is an interface (.xml, .xmlc, .xmlpy...), the island at the top of the window is its preview: unfolded, it shows the interface built from what is being typed, rebuilt as it changes, in the language chosen for the preview; a mistake shows its line instead.

The visual editor

It opens only when asked: a right click on an interface in the content drawer and Preview, the button of the island, or View > Preview the file (Ctrl+Shift+P). The file leaves its code editor for it, its unsaved changes with it, and it shows the same document five ways, kept in step:

  • Widgets: what can be added (the tags of the library and those the document declares). A double click adds inside the selection.
  • Tree: the elements; move up, down, out, in; duplicate, delete, wrap, unwrap; copy and paste as XML.
  • Preview: the interface built for real, in the language chosen above it, right to left included. A click selects; with Use the preview (F6) it reacts as the interface will. F7 opens it in a window of its own.
  • Properties: every attribute of the selection, by kind of value.
  • XML: the text, with completion; a mistake is underlined and listed in Problems while the last good version stays shown.

Close on the preview (or View > Close the preview) sends the file back to a code editor, and the panels of the visual editor go away.

Translations, build and run

The Translations panel shows the CSV tables as a grid: a row per key, a column per language. Ctrl+B builds, F5 builds and runs, Ctrl+F5 stops, with the tools of the language: CMake and the compiler, Cargo, go generate and go build, dotnet, zig build, Python, LuaJIT. What they write goes to Output; the errors and warnings of GCC, Clang, MSVC, rustc, Go, CMake and ravenc go to Build and onto the lines of the editors, brought back from the generated file to the line of the .xml.... Project > Build settings sets the build type, the folder of the Raven package and the generator, kept in .raven-ide.

Driving it from a script

The IDE can run without a window, which is how its tests work:

raven_designer --null --frames 2 --script "f 2 project /tmp/p demo C preview /tmp/p/demo/main.xmlc expectpanel panel.preview 1 do file.save_all"
raven_designer --null --script "nativeproject /tmp/p hello Rust expectfile /tmp/p/hello/src/main.rs Hello,~world!"

The commands are listed at the top of designer_script in tools/designer/main.c.

A rendering backend is a table of functions (RBackendVTable in raven_backend.h) given to Rbackend_register before Rinit with R_BACKEND_CUSTOM: it receives each frame as instances of rounded rectangles and draw commands. src/render/null/null_backend.c is a template. 29. What Raven does not do yet

  • Native Wayland (Wayland sessions work through XWayland).
  • Full OpenType shaping of complex scripts (Indic scripts, kerning); Arabic joining is done. The placement of the window of an input method.
  • In the text editor: several cursors, search and replace, folding, a language server client.
  • Dragging from a Raven window to another application. Glass over a native child window.
  • Mipmaps, a sub-allocator of GPU memory, recovery from a lost Vulkan device.
  • Node graph: knots, groups and comments, a minimap, undo (the application holds the model and its history). Timeline: nested tracks, curves between keys. Markdown: HTML, footnotes.
