Writing effects (shaders)

An effect is a fragment shader that Raven runs on a rounded rectangle of a widget. Raven comes with eight of them, and you can write your own in GLSL.

1. Quick start

A built-in effect, in XML: any Border can take an effect as its background. Its child is drawn over it.

<Border Effect="aurora" CornerRadius="18" Height="200">
    <Label Text="Tonight" TextSize="24" Slot.Padding="16" Slot.VAlign="Bottom"/>
</Border>

An effect of your own, in three steps:

  1. Write stripes.frag: 
    #version 450
#extension GL_GOOGLE_include_directive : require
#include "raven_effect.glsl"

vec4 raven_effect(RavenEffect fx) {
    float band = 0.5 + 0.5 * sin(fx.pixel.x * 0.25 - fx.time * 4.0);
    return mix(fx.color, fx.color2, band);
}
  2. Compile it: 
    glslangValidator -V -I<raven package>/include/raven/shaders stripes.frag -o stripes.spv
  3. Use it: 
    <Border Effect="stripes.spv" EffectColor="#1C1C1E" EffectColor2="#0A84FF" CornerRadius="12"/>

2. The built-in effects

Each one is created the first time it is used. In XML, Effect="name"; in C, Reffect_get(R_EFFECT_...) or Reffect_find("name"). EffectColor, EffectColor2 and EffectParams replace the defaults; EffectParams may give fewer than four numbers, the others keep their defaults.

3. How an effect is run

Raven draws its interface as a list of primitives, each a rectangle that a single fragment shader turns into its shape. An effect is one more kind of primitive whose fragment shader is yours. For every pixel of the rectangle, Raven:

  1. discards the pixels outside the clip rectangle of the widget;
  2. computes the distance to the edge of the rounded rectangle and discards the pixels outside it;
  3. calls your function raven_effect with where the pixel is, the size, the time, the two colors and the four parameters;
  4. multiplies what it returns by the coverage of the edge (anti-aliasing) and the opacity of the widget, and blends it over what is already drawn.

So an effect never deals with rounded corners, high DPI, clipping, opacity, premultiplied alpha or blending: it returns a color with a straight alpha, and Raven does the rest. The vertex stage, the pipeline layout and the bindings are those of the user interface; this is why an effect must be written with raven_effect.glsl.

4. Writing an effect

An effect file has exactly this shape:

#version 450
#extension GL_GOOGLE_include_directive : require
#include "raven_effect.glsl"

// any constants and functions of your own

vec4 raven_effect(RavenEffect fx) {
    // ...
    return vec4(red, green, blue, alpha);   // 0..1, straight alpha
}
  • Do not write main(), inputs, outputs or bindings: raven_effect.glsl declares them.
  • Names starting with raven_ are for you; names starting with rvn_ are internal and may change.
  • Return values outside 0..1 are clamped.

5. What the effect receives

The fields of RavenEffect
FieldTypeMeaning
fx.uvvec2Where the pixel is in the rectangle: (0, 0) top left to (1, 1) bottom right.
fx.pixelvec2The same in pixels, from the top left corner of the rectangle.
fx.sizevec2The size of the rectangle in pixels (it grows with the scale of the screen).
fx.screenvec2Where the pixel is in the window, in pixels: what raven_backdrop takes.
fx.edgefloatSigned distance to the edge of the rounded rectangle, in pixels: negative inside, 0 on the edge. Use it for borders and glows.
fx.timefloatSeconds. It wraps every hour; effects should only depend on how it changes.
fx.pointervec2Where the pointer is, in pixels from the top left corner of the rectangle, like fx.pixel (it may be outside the rectangle). Far away (below -1e5) when the pointer is not over the window or the effect does not follow it: test with raven_has_pointer(fx).
fx.hoverfloatHow much the pointer is over the widget, 0..1. On a Border it eases in and out in a fraction of a second.
fx.pressfloatHow much the widget is pressed (left button down over it), 0..1, eased the same way.
fx.color, fx.color2vec4The two colors of the look (EffectColor, EffectColor2), straight alpha.
fx.paramsvec4The four parameters (EffectParams, RShaderLook::params). Their meaning is the effect's.

7. Compiling to SPIR-V

Raven takes SPIR-V, not GLSL: the program does not carry a shader compiler. Both compilers of the Vulkan SDK work:

glslangValidator -V -I<raven>/include/raven/shaders effect.frag -o effect.spv
glslc -I<raven>/include/raven/shaders effect.frag -o effect.spv

In a CMake project, compile them as part of the build:

find_program(GLSLANG glslangValidator REQUIRED)
# the include folder of the Raven package, or include/ of a Raven source tree
set(RAVEN_SHADER_INCLUDE "${raven_DIR}/../../../include/raven/shaders" CACHE PATH "Folder of raven_effect.glsl")
add_custom_command(OUTPUT ${CMAKE_CURRENT_BINARY_DIR}/stripes.spv
    COMMAND ${GLSLANG} -V -I${RAVEN_SHADER_INCLUDE}
            ${CMAKE_CURRENT_SOURCE_DIR}/stripes.frag -o ${CMAKE_CURRENT_BINARY_DIR}/stripes.spv
    DEPENDS stripes.frag)
add_custom_target(effects ALL DEPENDS ${CMAKE_CURRENT_BINARY_DIR}/stripes.spv)

To ship the effect inside the executable, turn the .spv into a C array (for example with xxd -i) and give it to Rshader_create.

Declared tags make effects reusable:

<Widget Name="Hero" Title="">
    <Border Effect="aurora" CornerRadius="20" Height="220">
        <Label Text="{Title}" TextSize="28" Slot.Padding="20" Slot.VAlign="Bottom"/>
    </Border>
</Widget>
<Hero Title="Welcome back"/>

In C, on a Border

Rid shader = Rshader_create_from_file("stripes.spv", R_SHADER_ANIMATED);
RShaderLook look;
Rshader_look_defaults(shader, &look);    /* the defaults of a built-in effect, or white */
look.color[0] = 0.04f; look.color[1] = 0.52f; look.color[2] = 1.0f; look.color[3] = 1.0f;
look.radius = 12.0f;
Rborder_set_effect(border, shader, &look);

In C, from a paint callback

static void paint(Rid widget, RPainter* painter, float width, float height, void* user_data) {
    RShaderLook look;
    Reffect_get_defaults(R_EFFECT_NEON, &look);
    look.radius = 14.0f;
    look.params[0] = 2.0f;                       /* faster */
    Rdraw_rect(painter, 0, 0, width, height, 14.0f, 0.08f, 0.08f, 0.10f, 1.0f);
    Rdraw_shader(painter, Reffect_get(R_EFFECT_NEON), 0, 0, width, height, &look);
}

Passing NULL as the look uses the defaults of the shader. Several effects can be drawn in one paint callback; consecutive draws of the same shader are batched.

9. Reading what is behind

An effect created with R_SHADER_BACKDROP (EffectBackdrop="true") can read what was drawn before it with raven_backdrop and raven_backdrop_blur. Raven then captures the frame under the effect before drawing it, the same way it does for glass. This is how refraction, water, heat haze or magnifiers are written:

vec4 raven_effect(RavenEffect fx) {
    vec2 center = fx.size * 0.5;
    vec2 d = fx.pixel - center;
    float lens = 1.0 - smoothstep(0.0, min(fx.size.x, fx.size.y) * 0.5, length(d));
    vec3 seen = raven_backdrop(fx.screen - d * lens * 0.35).rgb;   /* magnified toward the middle */
    return vec4(seen, 1.0);
}
  • The sharp backdrop is a half-resolution copy of the frame: fine lines and small text look slightly soft through it, as they do through glass.
  • Only what was drawn before the effect is visible through it. Put the effect after (over) the content: in an Overlay, the later child is drawn last.
  • Each backdrop effect costs a capture of the area under it. Avoid tens of them in one window.

10. Animation

Raven only draws a window when something changes. An effect created with R_SHADER_ANIMATED, or drawn with RShaderLook::animate = R_TRUE (EffectAnimate="true"), keeps the window drawing frames while it is shown, so that fx.time moves. All built-in effects except spotlight are animated. An effect that does not depend on fx.time should not be animated: the window then sleeps between events and costs nothing.

Effects in .spv files used from XML are animated by default; write EffectAnimate="false" for a still one.

11. Following the pointer

Every effect knows where the pointer is: fx.pointer (pixels, from the corner of the rectangle), fx.hover and fx.press (0..1). The effects of Raven all use them; an effect of the application uses them if it wants. Guard with raven_has_pointer(fx), and weigh what the pointer does by fx.hover, so that the effect eases back to its rest when the pointer leaves:

vec4 raven_effect(RavenEffect fx) {
    vec4 color = mix(fx.color, fx.color2, fx.uv.y);
    if (raven_has_pointer(fx)) {
        vec2 d = (fx.pixel - fx.pointer) / (0.4 * max(fx.size.x, fx.size.y));
        float light = exp(-dot(d, d) * 3.0) * fx.hover;        /* a soft light under the pointer */
        color.rgb += light * (0.12 + 0.12 * fx.press);         /* brighter while pressed */
    }
    return color;
}
  • On a Border, fx.hover rises when the pointer enters the border or anything it holds, and falls when it leaves; fx.press follows the left button over it. Both are eased, so the effect never jumps.
  • With Rdraw_shader, they are 1 while the pointer is in the rectangle (and the left button is down there), else 0; set RShaderLook::hover and press to ease them yourself, for example with Rdraw_spring.
  • While the pointer is over it, an effect is drawn every frame, so that it follows the pointer even when it is not animated. It goes back to sleep when the pointer has left.
  • EffectPointer="false" (RShaderLook::pointer = R_FALSE) keeps an effect still: fx.pointer is then far away and fx.hover, fx.press are 0.
  • The pointer is that of the window: an effect can react to it before it is over the effect (fx.pointer outside the rectangle), for a glow that grows as the pointer comes near. It is only redrawn as the pointer moves while something animates the window, though; weigh such effects by fx.hover.

12. Examples

A pulse of light

vec4 raven_effect(RavenEffect fx) {
    float pulse = 0.5 + 0.5 * sin(fx.time * 3.0);
    float glow = exp(fx.edge / (6.0 + 10.0 * pulse));        /* brightest at the edge */
    return vec4(mix(fx.color.rgb, fx.color2.rgb, glow), 1.0);
}

A duotone image

/* RShaderLook::texture = the image; the two colors replace its shadows and its lights */
vec4 raven_effect(RavenEffect fx) {
    vec4 image = raven_texture(fx.uv);
    float light = dot(image.rgb, vec3(0.2126, 0.7152, 0.0722));
    return vec4(mix(fx.color.rgb, fx.color2.rgb, light), image.a);
}

Liquid glass (reads the backdrop)

vec4 raven_effect(RavenEffect fx) {
    float strength = fx.params.x > 0.0 ? fx.params.x : 6.0;
    vec2 flow = vec2(raven_fbm(fx.uv * 3.0 + fx.time * 0.25),
                     raven_fbm(fx.uv * 3.0 - fx.time * 0.2 + 7.0)) - 0.5;
    vec3 seen = raven_backdrop(fx.screen + flow * strength * 2.0).rgb;
    float rim = smoothstep(-6.0, 0.0, fx.edge);
    return vec4(mix(seen, fx.color.rgb, fx.color.a) + rim * 0.12, 1.0);
}

The examples of the repository (examples/effects) show every built-in effect and two effects of the application, wave.frag and liquid.frag; move the pointer over them.

13. Performance

  • The shader runs once per pixel of the rectangle, every frame while it is animated. A full-window effect at 4K is about 8 million calls per frame: keep loops short (the built-in effects use at most fifteen noise lookups per pixel).
  • raven_fbm is five noise lookups; raven_noise is four hashes. Prefer sin and smoothstep where they are enough.
  • An effect that is not animated is drawn only when the window is redrawn.
  • Backdrop effects add a capture and a blur of the area they cover.
  • The first time an effect is drawn in a window with a new color format, Raven creates its pipeline. It is kept for the rest of the run.

14. When nothing shows

Symptoms and causes
SymptomCause
The error callback says "this is not SPIR-V"The file is GLSL, or the path is wrong. Compile it with -V (glslangValidator) or with glslc.
"the effect shader cannot be used"The shader does not match the interface of Raven: it was not written with raven_effect.glsl, or it declares its own inputs, outputs or bindings.
The rectangle shows one flat colorThe backend has no effects (R_BACKEND_NULL, or a custom backend whose CreateShader is NULL).
The effect does not moveIt is not animated: create the shader with R_SHADER_ANIMATED or set EffectAnimate="true".
The backdrop is whiteThe shader was not created with R_SHADER_BACKDROP (EffectBackdrop="true").
Nothing behind shows throughThe effect is drawn before the content: place it after it (later in an Overlay).
Banding in dark gradientsAdd a little noise: color += (raven_hash(fx.pixel) - 0.5) / 255.0;

15. Rules and limits

  • Effects run with the Vulkan backend. On other backends the rectangle is filled with the first color.
  • An effect is a fragment shader only: it cannot change the geometry. To draw outside a widget, give the effect a larger rectangle (a larger Border, or Rdraw_shader with a larger rectangle, within the clip of the widget).
  • Bindings are fixed: set 0 is the texture of the look, set 1 the backdrop. An effect cannot declare its own uniform buffers; it receives two colors and four numbers. For more data, encode it in a texture and read it with raven_texture.
  • The interface between Raven's vertex shader and effects (raven_effect.glsl) is versioned with Raven: recompile your effects with the header of the version you ship with.
  • Rshader_destroy waits for the GPU to finish with the shader; destroy shaders when the program ends or when they are no longer used, not every frame.

For backend writers

A custom backend that wants effects fills CreateShader and DestroyShader in its RBackendVTable and draws R_DRAW_SHADER commands: the instances are R_PRIM_SHADER primitives whose fields are described in raven_backend.h. A backend without them leaves both NULL.
